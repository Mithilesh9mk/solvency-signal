# solvency-signal

An early-warning model for corporate financial distress, with a neural network as the deep learning comparison.

> Status: Phases 8 to 10 done (the Streamlit app with the Phase 9 blank rule and the Phase 10 four-ratio Quick check, deployed). Phase 7 was the Attr21 missingness analysis (descriptive). Phase 6 gave SHAP explanations of the frozen LightGBM + Platt model. The test split was read once, in Phase 5, and is locked. A separate US model (time split, LightGBM + Platt headline) has its validation report and a one-shot test result, both below.

## Problem

Predict which companies are likely to go bankrupt in the following year, early enough for the warning to be useful, and say how
sure the model is. Probabilities are calibrated and mapped to Low, Watch and High bands. The models rank firms in historical data
and are not a lending decision tool.

## Data

| Role | Dataset | Notes |
|---|---|---|
| Primary | Polish companies bankruptcy, `5year.arff` (UCI 365, CC BY 4.0) | 5,910 firms, 64 financial ratios, label is bankruptcy within 1 year |
| Second model | American companies, NYSE and NASDAQ 1999 to 2018 (CC BY 4.0) | 18 raw accounting variables, no operating cash flow; one-year-ahead label derived by this project, time split, protocol in docs/us_protocol.md |
| Optional benchmark | Taiwanese bankruptcy prediction (UCI) | Most features pre-scaled to 0 to 1, some contain values near 1e10 |

Feature names, formulas, data quality flags and split sizes: [reports/data_report.md](reports/data_report.md).

Citation: Tomczak, S. (2016). Polish Companies Bankruptcy [Dataset]. UCI Machine Learning Repository. https://doi.org/10.24432/C5F600

License: Creative Commons Attribution 4.0 International (CC BY 4.0), as stated on the UCI dataset page (checked 2026-10-17). This project changed the data: exact duplicates dropped, a stratified random 70/15/15 split, and model scores derived from it. The UCI page does not state the sector of the companies (UNVERIFIED).

## Method

- **Data and split:** exact duplicates dropped, then a stratified random 70/15/15 split with seed 42.
- **Models:** logistic regression (clip, impute, scale), LightGBM on raw ratios, and TremorNet, a small PyTorch MLP with
  rank-based input scaling and early stopping on an inner holdout. No class reweighting, fixed hyperparameters.
- **Validation strategy:** PR AUC as the primary metric, bootstrap confidence intervals, train-only cross-validation for
  any configuration choice. Validation is used to choose between the three models and, by user decision, to fit the
  band cuts (see docs/decisions.md), so validation numbers at the cuts are in-sample.
- **Explanations:** TreeSHAP on train and validation only, on the calibrated log-odds scale after a check that the Platt
  slope conversion reproduces the calibrator. Feature names are the UCI formulas, with doubtful definitions marked UNVERIFIED.
  Categories (Liquidity, Leverage, Profitability, Cash Flow, Other) are assigned by this project, since UCI gives none.
- **Test:** read once in Phase 5 with frozen artifacts and a pre-stated verdict rule. Nothing was changed afterwards.
- **Calibration (Phase 4):** Platt, isotonic or none, fitted on 5-fold out-of-fold predictions on train, chosen by
  cross-validated log loss. Low, Watch and High bands are set from a rule stated before results.
- Fixed random seed 42 throughout.

### Flags

1. Validation set is small, so metrics carry wide intervals. Use the CIs.
2. Random split only. No company id or year exists, so a time-based split is impossible.
3. Attr21 (sales_growth) needs last year's sales, and it is the second strongest feature.
4. The test split was read once, in Phase 5, and is locked. Nothing may be tuned on it. Any further model change needs new data.
5. Validation has only 61 bankrupt firms and ECE uses 10 equal-frequency bins of about 87 firms (about 6 positives each), so ECE and the reliability points are noisy. Read them with the CIs.
6. Calibrators and bands were fitted on 5-fold out-of-fold scores of the train split (286 bankrupt). The saved models are refit on all of train, so they are slightly stronger than the fold models the calibrators saw. Direction of the bias is not verified.
7. Cost ratios 5:1, 10:1 and 20:1 are assumptions, not estimates from any lender or data.
8. Band cuts are fitted on validation by user instruction, so validation precision and recall at the cuts are in-sample and optimistic. The independent check is the same cuts applied to train out-of-fold scores.
9. The High precision floor 0.60 was set after an earlier precision-floor diagnostic and the validation tradeoff table had been seen, so it is not a blind choice.
10. logistic_regression: recall of the flagged bands on train OOF (0.797) is below the 0.80 target the cut reached on validation.
11. logistic_regression: isotonic gives exactly 0 or 1 to 19 validation firms (log loss clips at 0.0001), which is overconfident and costs log loss.
12. lightgbm: recall of the flagged bands on train OOF (0.769) is below the 0.80 target the cut reached on validation.
13. lightgbm: the Watch band is thin (16 validation firms with 4 bankrupt, 52 train OOF firms), because the 80% recall cut (0.1736) and the precision cut (0.2403) are close. Its rate rests on very few positives.
14. lightgbm: isotonic gives exactly 0 or 1 to 151 validation firms (log loss clips at 0.0001), which is overconfident and costs log loss.
15. neural_net: High-band precision on train OOF (0.575) is below the 0.60 floor the cut reached on validation.
16. neural_net: isotonic gives exactly 0 or 1 to 33 validation firms (log loss clips at 0.0001), which is overconfident and costs log loss.
17. Phase 5: The Watch band is thin on test (16 firms, 3 bankrupt), so its rate carries almost no information. Fewer than 30 firms is the thin-band line.
18. Phase 5: neural_net has a higher test PR AUC (0.803) than the headline model (0.797). The intervals overlap almost completely, so neither model can be called better on this test set. By protocol it is reference only and does not replace the headline; the user may choose to revisit.
19. Phase 5: Change in PR AUC from validation to test: lightgbm +0.014, logistic_regression +0.121, neural_net +0.081. The models do not move together by the same amount, so the validation gaps between the three models should not be over-read.
20. Phase 5: The headline PR AUC is higher on test than on validation. That is the opposite of the expected-optimism direction stated before the run, so the optimism sources do not explain this gap. It is small against the interval width, and the most plausible reading is sampling noise.
21. Phase 5: One test set of 61 bankrupt firms. Every interval is wide, and this is a single draw, not a repeated trial.
22. Phase 5: Random split only, no company id or year, so this says nothing about performance on future years.
23. Phase 5: Calibrators and band cuts were fitted on fold models, while the scored model is refit on all of train. The test run does not isolate this mismatch.
24. Phase 5: Attr21 (sales_growth) needs last year's sales, and it is the second strongest feature.
25. Phase 5: Nothing was retrained, recalibrated or re-cut after seeing these results, by protocol.
26. Phase 6: SHAP describes what the model does, not what causes bankruptcy. A large contribution is a model pattern, not a cause.
27. Phase 6: Correlated ratios split credit, so one ratio can look less important because a close twin shares its signal. Known near twins: Attr2 and Attr17 (exact reciprocals), Attr9 and Attr36 (near duplicates). Category sums are only a partial remedy.
28. Phase 6: The five categories are assigned by this project from each formula. They are not in the UCI description or the dictionary. Borderline cases are Attr27, Attr30, Attr33, Attr34, Attr37 and Attr58. The full map is in the appendix.

## Limitations

Random split with no time ordering, a small validation set (wide confidence intervals), one country and one year file,
and a feature (`sales_growth`) that needs the previous year's sales. See the Flags above and the reports for detail.

## How to run

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
```

Prepare the data (reads the raw zip, writes splits to `data/processed`):

```bash
python -m src.preprocess
```

Run the tests:

```bash
python -m pytest tests
```

Train all models (baselines and neural network), score them on validation, then draw the curves:

```bash
python -m src.train
python -m src.evaluate
```

Calibrate, set risk bands and write the Phase 4 report (train and validation only), then refresh the generated state files:

```bash
python -m scripts.run_phase4
python -m scripts.update_state --phase "Phase 4: calibration, thresholds and risk bands"
```

Final one-shot test evaluation (already run; the script refuses to run a second time):

```bash
python -m scripts.final_test_eval
python -m scripts.update_state --phase "Phase 5: final test evaluation"
```

SHAP explanations (train and validation only), then refresh the generated state files:

```bash
python -m scripts.run_phase6
python -m scripts.update_state --phase "Phase 6: SHAP explanations"
```

Attr21 missingness analysis (train and validation only), then refresh the generated state files:

```bash
python -m scripts.run_phase7_attr21
python -m scripts.update_state --phase "Phase 7: Attr21 missingness"
```

Build the app numbers and demo firms (train and validation only), then run the app locally:

```bash
python -m scripts.run_phase8_prep
streamlit run app/streamlit_app.py
```

The first tab, Quick check, takes four ratios (current ratio, debt-to-equity, net profit margin and a cash earnings ratio) and returns a 1 to 10 score, a band and the observed bankruptcy rate of Polish training firms with that score. It is a separate small model (Phase 10, `src/quick.py`, fitted model in `artifacts/quick/quick_model.json`) and ranks firms much worse than the full 64-ratio model, with the numbers in the Phase 10 block above. The cash earnings ratio, (net profit + depreciation) / total liabilities, is a proxy because the data has no operating cash flow.

The remaining tabs use the 64-ratio model. The app is a screening signal for firms like those in the Polish data. It is not lending advice, and it was checked on a random
split only. It does not score a firm with Attr21 (sales growth), Attr24 or Attr27 blank (the Phase 9 rule, read from `reports/phase9_blank_rule.json`), and it does not score a firm with more than 6 other
blank attributes. Uploaded data is processed in memory and is not written to disk by this app. At start-up it checks the model
and calibration files against the hashes in `artifacts/phase5_protocol.json` and stops on a mismatch. To deploy on Streamlit
Community Cloud, point it at `app/streamlit_app.py` (it uses `app/requirements.txt`). It is deployed this way, see Live app below.
